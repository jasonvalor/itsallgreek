# Purpose

This document defines the purpose, scope and success criteria of the project.

Every AI agent, developer or contributor must read this document before reading any other documentation.

This document takes priority over all implementation decisions.

---

# Project Goal

Create a premium, mobile-first website for **It's All Greek**, a Greek restaurant located in Nieuwerkerk aan den IJssel.

The website should function as a modern digital business card that communicates the restaurant's atmosphere, builds trust and makes it effortless for visitors to view the menu, contact the restaurant or place an order.

The website is intentionally simple.

Every design and technical decision should support clarity, speed and quality.

---

# Primary Objectives

1. Create an outstanding first impression.
2. Reflect the authentic atmosphere of the restaurant.
3. Increase takeaway and delivery orders.
4. Encourage visitors to dine in.
5. Present the menu clearly.
6. Make contacting the restaurant effortless.

---

# What This Website IS

- A premium restaurant website.
- Mobile-first.
- Fast.
- Minimal.
- Easy to maintain.
- SEO-friendly.
- Production-ready.
- Component-based.
- Built with reusable architecture.

---

# What This Website IS NOT

Do NOT build:

- An ordering system.
- A shopping cart.
- User accounts.
- Customer login.
- Checkout flow.
- Payment integration.
- Loyalty system.
- Reservation platform.
- CMS unless explicitly requested.
- Unnecessary animations.
- Decorative features without purpose.

Ordering happens via:

- Thuisbezorgd
- Telephone
- WhatsApp (if added later)

# Design Principles

Every page should feel:

- Warm
- Modern
- Premium
- Calm
- Mediterranean
- Authentic

Never feel:

- Generic
- Busy
- Corporate
- Cheap
- Overdesigned

Less is more.

Whitespace is intentional.

Photography is more important than text.

- Performant.
- SEO-friendly.

---

# Development Workflow

Before writing code:

1. Read every file inside `/docs`.
2. Review all approved assets inside `/design`.
3. Understand the existing component structure.
4. Explain the implementation plan if major structural changes are required.

After implementation:

- List every modified file.
- Explain why it changed.
- Identify potential improvements separately.

Never silently redesign.

Never silently refactor.

# Success Criteria

The project is successful when:

- The website matches the approved designs.
- The experience feels premium.
- The codebase is clean and maintainable.
- Performance is excellent.

# Golden Rules

- Build exactly what has been approved.
- Reuse before creating.
- Simplicity beats complexity.
- Consistency beats creativity.
- Ask instead of assuming.
